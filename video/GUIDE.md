# Как сделан ролик BETTING LAB — и как повторить это в Claude Code на своём ПК

Здесь описан весь конвейер: какие программы нужны, что делает каждый шаг и какие
команды запускать. Описание повторяет то, что реально использовалось для ролика
«Ставки на экспрессы».

---

## 1. Общая идея

Ролик не монтируется вручную в видеоредакторе. Он **описан кодом**:

```
сценарий (DOCX) ─┐
озвучка (MP3) ───┼─► расшифровка с таймкодами слов ─► сцены в коде (React/Remotion)
картинки (PNG) ──┘                                      │
                                                        ▼
                         рендер кадров (Remotion + Chrome) ─► видео без звука
                         сведение звука (ffmpeg)          ─► звуковая дорожка
                                                        ▼
                                 склейка + нормализация громкости (ffmpeg)
                                                        ▼
                                          BETTING_LAB_express_full.mp4
```

Главный трюк, который делает ролик «живым»: **озвучка расшифровывается с точностью
до слова** (Whisper). Поэтому каждая надпись, цифра или галочка появляется ровно
в момент, когда диктор произносит нужное слово.

## 2. Что установить на ПК (Windows)

| Программа | Зачем | Как поставить |
|---|---|---|
| **Node.js 20+ (LTS)** | Remotion, скрипты рендера | https://nodejs.org или `winget install OpenJS.NodeJS.LTS` |
| **ffmpeg** | звук, склейка, нормализация громкости | `winget install Gyan.FFmpeg`, затем перезапустить терминал и проверить `ffmpeg -version` |
| **Python 3.10+** | расшифровка озвучки | https://python.org (при установке отметить *Add to PATH*) |
| **Git** | скачать проект | `winget install Git.Git` |
| **Claude Code** | агент, который будет править сцены | https://docs.claude.com/claude-code |

Chrome отдельно ставить не нужно: Remotion сам скачает свою версию при первом рендере.

Требования к железу: чем больше ядер процессора, тем быстрее. В песочнице было
всего **2 ядра**, и 15-минутный ролик рендерился ~1 ч 40 мин. На обычном ПК
с 8–16 потоками будет в 3–6 раз быстрее.

```powershell
git clone https://github.com/Atlascodeweb/videobet.git
cd videobet

cd video
npm install

python -m venv .venv
.venv\Scripts\activate

```

### Положить медиафайлы

Медиа не хранится в git (слишком тяжёлое). Разложите файлы так:

```
video/public/media/voice.mp3        ← озвучка ElevenLabs
video/public/media/disclaimer.mp4   ← готовый дисклеймер (10 с)
video/public/media/outro.mp4        ← готовое аутро (15 с)
video/public/img/*.png              ← картинки сцен (1672×941 или 16:9)
```

Картинки названы **по содержанию**, и код ссылается на эти имена:

```
analyst-monitors  bait-hook      ball-net        chain-break    cliff-trophy
coins-city        couch-bet      drowning-ring   eggs-basket    fan-nervous
floor-despair     funnel-gold    glass-dice      iceberg        jenga-fall
jenga-pull        keeper-dive    kitchen-shock   lab-microscope laptop-notes
neon-coupon       phone-green    phone-smile     players-celebrate
puzzle-lamp       referee-rain   rope-bridge     runner-fall    spiral-stairs
tightrope         tired-laptop   tunnel          winner-confetti
```

`phone-green.png` — телефон с зелёным экраном: в код вшиты координаты этого
экрана, и поверх него рисуется интерфейс со списком матчей.

Для сцен с размытым фоном нужны заранее размытые копии (это ускоряет рендер):

```powershell
python -c "from PIL import Image,ImageFilter;import glob,os;os.makedirs('public/img/blur',exist_ok=True);[Image.open(f).convert('RGB').filter(ImageFilter.GaussianBlur(8)).save('public/img/blur/'+os.path.basename(f)[:-4]+'.jpg',quality=90) for f in glob.glob('public/img/*.png')]"
```
(нужен `pip install pillow`)

Звуковые эффекты (вжух, удар, щелчок, нарастание) синтезируются через ffmpeg,
сторонние сэмплы не используются. Они уже лежат в репозитории, а пересоздать их можно так:

```powershell
node scripts/make-sfx.mjs
```

## 4. Шаги конвейера

### Шаг 1. Расшифровка озвучки с таймкодами слов

```powershell
python scripts/transcribe.py public/media/voice.mp3 out/transcript
```

Используется **faster-whisper**, модель `small`, на процессоре. 15 минут озвучки
обрабатываются примерно за 15–25 минут. Получаются два файла:

* `out/transcript.txt` — строки вида `Сегодня@3.42 поговорим@3.84 об@4.48 экспрессах,@4.74`
* `out/transcript.json` — то же, плюс границы фраз.

Числа после `@` — секунды от начала озвучки. Именно их подставляют в сцены.

### Шаг 2. Сцены в коде

| Файл | Что внутри |
|---|---|
| `src/theme.ts` | цвета, шрифт Montserrat, 30 fps, **позиция дисклеймера** (`DISC_AT = 48.4`, `DISC_LEN = 10`) |
| `src/lib.tsx` | базовые эффекты: фон с медленным наездом камеры (Ken Burns), зерно плёнки, частицы, вспышки, тряска камеры, появление текста по буквам, блик |
| `src/kit.tsx` | готовые типы сцен: `Chapter` (заставка главы), `Statement` (надписи по таймкодам), `Quote` (цитата), `ProbChain` (цепочка вероятностей 80%×5), `MatchRun` (карточки матчей ✓/✕), `BigStat` (большое число), `ListCard`, `Compare` (две колонки), `CouponScene` (купон), `Money`, `Survivorship` (скриншот выигрыша и гора проигрышей), `EVChart` (график −18,5%), `CTA` (подписка) |
| `src/scenes/intro.tsx` | вручную собранное вступление и начало первой главы |
| `src/Full.tsx` | **таймлайн всего ролика**: массив `CUES` (какая сцена, с какой секунды, с какими параметрами), звуковые эффекты, вставка дисклеймера и аутро |
| `src/TestMinute.tsx` | тестовая минута |

Пример одной сцены из `Full.tsx`:

```tsx
st(153.2, {                        // сцена начинается на 153,2 с озвучки
  img: 'puzzle-lamp.png',          // фоновая картинка
  lines: [
    {t: 'Коэффициент [1,20]', at: 154.4, size: 110},   // [..] — подсветка цветом
    {t: 'воспринимается как очень вероятный исход', at: 157.5, sub: true},
  ],
}),
```

Сцена длится до начала следующей, а между сценами есть плавное перетекание.
Время в коде — **время озвучки**. Сдвиг на 10 секунд дисклеймера функция `vf()`
добавляет сама.

### Шаг 3. Просмотр и правка

```powershell
npm run studio
```

Откроется Remotion Studio в браузере: можно листать таймлайн, смотреть любой кадр
и сразу видеть правки в коде.

Чтобы получить отдельный кадр картинкой (удобно, чтобы Claude Code проверил результат сам):

```powershell
npx remotion still Full out/check.jpg --frame=4620 --image-format=jpeg
```

Номер кадра считается так: `(секунда_озвучки + 10) × 30`, если момент после
дисклеймера, и `секунда × 30`, если до него.

### Шаг 4. Рендер полного ролика с прогрессом

Откройте два терминала:

```powershell
npm run progress        # страница прогресса: http://localhost:3333
npm run render:full     # рендер по главам
```

Что делает `scripts/render-full.mjs`:

1. Рендерит видео **по главам** (11 частей) без звука, `--crf=18` (высокое качество).
   Каждая готовая часть помечается файлом `.done`. Если рендер прервать,
   повторный запуск продолжит с той же главы. Чтобы перерендерить одну главу после
   правки, удалите `out/chunks/NN.mp4.done` и запустите команду снова.
2. Сводит звук скриптом `scripts/mix-audio.mjs`: голос, разрезанный под дисклеймер,
   звук дисклеймера и аутро, ~160 звуковых эффектов с точными таймкодами,
   срез частот ниже 40 Гц. Это занимает секунды.
3. Склеивает части и накладывает звук. Громкость нормализуется до **−14 LUFS**
   (стандарт YouTube): `loudnorm=I=-14:TP=-1.2`.

Результат: `out/BETTING_LAB_express_full.mp4`.

Параметр `--concurrency=2` в `render-full.mjs` задаёт, сколько кадров рендерится
одновременно. На ПК с 8+ ядрами поставьте 4–8, и будет заметно быстрее.

## 5. Как работать с Claude Code

В папке `video/` лежит файл **`CLAUDE.md`**: Claude Code читает его автоматически
и узнаёт из него, как устроен проект. Запускайте Claude Code **из папки `video`**.

Почему «он не умеет как ты»: обычно у него просто нет этого конвейера и привычки
проверять себя. Решение — дать ему готовый проект (этот репозиторий) и просить
работать по шагам, проверяя результат кадрами.

### Готовые запросы

**Новый ролик по тому же шаблону:**
> Новый выпуск. Сценарий: `scenario.docx`, озвучка в `public/media/voice.mp3`, картинки в `public/img`.
> 1) Запусти `scripts/transcribe.py` и прочитай `out/transcript.txt`.
> 2) Прочитай сценарий, разбей на главы и сцены.
> 3) Перепиши массив `CUES` в `src/Full.tsx` и `CHUNKS` под новые таймкоды, используя сцены из `src/kit.tsx`. Подбери картинки по смыслу.
> 4) Отрендери 10–15 ключевых кадров через `npx remotion still`, посмотри их и исправь наложения и переносы текста.
> 5) Сначала сделай тестовую минуту, потом запусти полный рендер.

**Точечная правка:**
> На 4:12 надпись налезает на картинку. Отрендери этот кадр, посмотри и поправь сцену в `src/Full.tsx`, затем перерендери только эту главу.

**Новый тип анимации:**
> Добавь в `src/kit.tsx` сцену «таблица коэффициентов» в стиле остальных (стеклянные карточки, `glow`, `Reveal`) и используй её на 5:30.

### Важно сказать Claude Code

* После каждой правки он должен **смотреть кадры** (`remotion still`), а не только запускать проверку типов.
* Время в `CUES` — секунды озвучки из `out/transcript.txt`.
* Если дисклеймер переносится в другое место, `DISC_AT` меняется в трёх местах: `src/theme.ts`, `scripts/render-full.mjs`, `scripts/mix-audio.mjs`. Списки глав `CHUNKS` в `Full.tsx` и `starts` в `render-full.mjs` должны совпадать.
* Долгий рендер нужно запускать в отдельном терминале, а не внутри Claude Code: у него ограничено время на одну команду.

## 6. Звук: как сделать так же, если Claude «не слышит»

Мне тоже не нужно было слушать. Звуки здесь не подбираются на слух, а **собраны
из формул** (ffmpeg) и **расставлены по таблице таймкодов**. Claude Code может
повторить это один в один, если не даёт ему придумывать своё.

**Что звучит в ролике.** Библиотека из 24 файлов в `public/sfx`. Все они собраны
по одному рецепту: чистые синусы, мягкая атака, короткое эхо.

| Имя в коде | Файлы | Как звучит | Когда | Громкость |
|---|---|---|---|---|
| `tick` | 5 вариантов | короткий мягкий «дзынь» на 5 разных нотах | пункт списка, строка купона | 0,40–0,50 |
| `success` | 3 | две ноты вверх, «динь-дон» | галочка ✓, «зашёл» | 0,50 |
| `pop` | 3 | мягкий «пузырёк» | появление карточки, кнопки | 0,60 |
| `shimmer` | 2 | тихий блеск, высокие колокольчики | золотые цифры, выплата, выигрыш | 0,45–0,50 |
| `fail` | 2 | две ноты вниз, мягко | ✕, «проигрыш» (вместе с `impact`) | 0,40–0,55 |
| `impact` | 4 | глубокий мягкий удар с эхом | важная цифра, заставка главы | 0,35–0,70 |
| `riser` | 4 | плавное нарастание, 1,6 с | за 1,2 с до главы или большого результата | 0,25–0,35 |
| `whoosh` | 1 | почти не слышен | смена сцены | 0,30 |

В коде пишется только имя (`'tick'`), а конкретный вариант (`tick.wav`, `tick_2.wav` …)
скрипт `mix-audio.mjs` выбирает **сам по кругу**, поэтому одинаковый файл никогда
не звучит два раза подряд. Чтобы добавить вариант, создайте файл `имя_N.wav`
(например, допишите его в `scripts/make-sfx.mjs`), и он сразу попадёт в ротацию.

Всего 177 звуков на 15 минут. Музыки и фона нет.

**Почему у Claude Code получается хуже.** Скорее всего, он создаёт новые звуки
или берёт другие файлы. Правильно так:

1. Использовать **только файлы из `public/sfx`** этого репозитория. Новые варианты добавлять только через `scripts/make-sfx.mjs` по тому же рецепту. Если он их
   перезаписал, верните оригиналы: `git checkout -- public/sfx`.
2. Ставить звуки **только через массивы `sfx` в `src/Full.tsx`**, формат
   `[секунда озвучки, имя, громкость]`, по таблице выше.
3. Сводить готовым скриптом `scripts/mix-audio.mjs`. Его сам запускает `npm run render:full`.

Готовый запрос для Claude Code:
> Звуки не создавай и не заменяй. Используй только имена `tick, success, pop, shimmer, fail, impact, riser, whoosh` из `public/sfx` по правилам из раздела «Sound design» в `CLAUDE.md`. Расставь их в массивах `sfx` в `src/Full.tsx` по таймкодам из `out/transcript.txt`, затем собери звук через `node scripts/mix-audio.mjs` и проверь громкость и спектрограмму командами из `CLAUDE.md`.

**Как Claude проверяет звук без ушей.** Командами из `CLAUDE.md`:
* громкость всего ролика (−14 LUFS);
* уровень в паузах между фразами (тише −45 дБ означает, что гула нет);
* **спектрограмма**: звук превращается в картинку, а картинки Claude смотреть умеет.
  Щелчок выглядит как пара ярких точек на 1,9 и 2,85 кГц, нарастание — как косая
  линия вверх, удар — как короткое пятно в самом низу. Длинная горизонтальная полоса внизу означает гул, и это ошибка.

## 7. Частые проблемы

| Проблема | Решение |
|---|---|
| Гул или шум на фоне | Не добавлять синтезированный «эмбиент» из низких частот (в этом ролике его убрали). Для фоновой музыки берите готовый трек и подмешивайте тихо, примерно −28 dB под голосом. |
| `ffmpeg не найден` | Перезапустить терминал после установки, проверить `ffmpeg -version`. |
| Рендер очень медленный | Увеличить `--concurrency`. Не использовать CSS `backdrop-filter` и большие `blur()`; размытие фонов делать заранее (папка `public/img/blur`). |
| Whisper ошибается в названиях | Это не страшно: таймкоды берутся по словам, а текст на экране пишется из сценария. |
| Текст вылезает за край | Отрендерить кадр, уменьшить `size` у строки или сократить текст. |
